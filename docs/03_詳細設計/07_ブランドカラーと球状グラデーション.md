# ブランドカラーとロゴ

2026-10-24、ユーザーが全体彩色とテーマ背景の白無地ロゴの比較を確認し、「okではそれで進めて」と採用を指定した。本書はAcecore公式・Systems・Schools・Designsの現行基準。ファイル名は既存の参照先を保つため変更していない。

- 最新のユーザー指示、本書、採用SVG、各サイトの既存実装、過去の検討資料の順に判断する。UI・配色・ロゴの変更前に本書を読む。
- 採用見本は[確認された比較](https://ce2e5901.acecore-net.pages.dev/brand-preview#theme-range)。明背景では全体を同じテーマの流れ、色背景では中央も含む白無地とする。全4サイトの公開比較も採用仕様へ同期する。
- 旧「中央だけテーマカラー」「中央は不変」「中央を色付きのまま濃背景へ載せる」「黒/淡色の材質区分」は失効した。旧承認HTMLと[中央・外周の質感調整記録](https://github.com/acecore-systems/acecore-net/blob/87ead70745fe040e5c2dd9af56c0e401d8cd47f0/docs/03_詳細設計/07_ブランドカラーと球状グラデーション.md)は履歴であり現行仕様ではない。

## 採用ロゴ

### 明るい背景

全6描画pathへ同一の有彩色radialを適用する。外周と中央、暗い材質と薄い材質で別の色面を作らない。白いハイライト、黒沈み、金属的な反射筋や折り目は加えない。左上から右下へ広く円弧状に色をつなぐ。

| サイト  | 色停止点                                                            |
| ------- | ------------------------------------------------------------------- |
| 公式    | 0% #2675df → 50% #0656d9 → 100% #17459d                             |
| Systems | 0% #8950c5 → 50% #765bd0 → 100% #0656d9                             |
| Schools | 0% #39a86b → 50% #278b91 → 100% #0656d9                             |
| Designs | 0% #e6b847 → 25% #e98f85 → 50% #d780ba → 75% #8970cf → 100% #0656d9 |

SVGのviewBoxは375×374.999991。主radialはuserSpaceの起点80/72、半径380/340（gradientTransform: matrix(380 0 0 340 80 72)）。全path/clip座標・比率・余白を保持する。CSSの--logo-paintは全ロゴ領域を基準に ellipse 101.333% 90.667% at 21.333% 19.2% と同じ停止点へ同期する。旧--sphere-paintは廃止し、球だけの白光沢tokenを残さない。

### テーマカラー背景

背景側へ上表のpaletteを使い、ロゴは中央を含め全6描画pathを#ffffffの単色にする。白版SVGにはgradient定義を持たせない。テーマの背景は ellipse 120% 135% at 0% 0% の広いradial。説明captionは白い読み面へ分ける。

通常ページは白主体のまま。ロゴのために全footerや全sectionを色面へ変えず、既存の色背景上で使う場合やOGなどの必要な箇所だけテーマ背景＋白版へ揃える。

### 画像の選択とfavicon

- 文書内imgは実背景で明示選択する。白いheader/footerは/logo.svg、テーマ背景は/logo-on-dark.svg。OSがdarkであることだけを理由に白いheaderのロゴを白くしない。
- /favicon.svgは専用asset。明外観は全体彩色、暗外観はテーマ背景rectと白無地ロゴへCSS mediaで切り替える。元の形状・余白を縮めず背景を追加する。375の正方形基準で背景radialは起点0/0、半径450/506.25。
- 文書内imgにadaptive faviconを流用せず、全白filterや白い四角の下地だけで代用しない。
- 公式のコード生成OGは青テーマ背景＋白版。Designsのコード生成OGは白読み面上なので全体彩色版を使う。文字・構図を保持しロゴと必要な背景だけ同期する。写真を使うSchools/SystemsのOGは差し替えない。

## UIの色と使用量

- 共通青は#0656d9。Systems紫#8950c5、Schools緑#39a86b、Designsは黄・橙・ピンク・紫から青への多色。似た色を独立追加せず名前付きtokenで管理する。
- 白いheader/footerのAcecore文字は共通青、事業名は指定色。Designsの小さい名前は読みやすい#986000 → #b33e71 → #8146ae → #0656d9を使う。名前も併記し、色だけで識別させない。
- テーマ色はロゴ・名称・短いラベル・リンク・主要CTA・選択状態・要所の罫線に絞る。全UIで一貫させることは全要素の着色を意味しない。
- 通常のh1/h2/h3、長文、料金数値は原則#20252b。白い読み面を主体とし、普通の表枠や区切りは中立色。全sectionをwashで埋めない。
- UI操作部品の--paint、文字用濃色、washは既存の読みやすい組み合わせを保持する。ロゴ全体彩色の採用は本文や料金の色変更を意味しない。Schoolsの主色に小さい白文字をそのまま載せない。
- 成功・警告・エラーの意味色、写真・実作品・記事図の内容上の色は維持する。公式内の部門名はSystems紫・Schools緑・Designs多色。

## 保全と検証

写真・Hatt・実作品・図・本文・価格・条件・翻訳・CMS・フォーム・検索・AI・多言語経路を保持する。画像の差し替えは個別指示が必要。コード生成ブランドOGとロゴSVGの今回許可された色表現だけを更新する。

変更時は既存配置、明暗外観、16/32/64pxと拡大、desktop/mobile、OGを確認する。path/clip/余白/比率を機械比較し、全体彩色版と全白版、faviconの背景切替を検証する。build・format・diff checkと必要な既存検証を実行し、ローカル・CI・Preview・マージ・本番を別の状態として記録する。
