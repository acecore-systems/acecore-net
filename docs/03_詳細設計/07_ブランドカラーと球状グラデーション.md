# ブランドカラーと球状グラデーション

2026-10-23、ユーザーが配色・球状グラデーション・ヘッダー文字色を承認し、「適切な場所に記録し常にこれをもとに」「全てこれをもとに進めて」と指定した。Acecore公式、Systems、Schools、Designsの共通基準を本書に記録する。

## 正本と優先順位

- 本書と[承認済みの配色見本](参考画像/ブランドカラー承認見本.html)を、今後のUI・ロゴ・装飾の変更前に確認する。見本は会話で承認された最終版を保存したもので、仮コピー・比較レイアウトを本番コンテンツとして採用する指示ではない。
- 新しいユーザー指示、本書と承認見本、各サイトの既存実装、過去の検討資料の順に判断する。基準を変更する際は理由と承認を記録し、見本・トークン・実装を一緒に更新する。
- `06_元画像の復元と部門カラー.md` の旧色表・旧追補、および途中案のSchools灰色、Systemsシアン、Designs単色紫、青の面積比率指定は配色の現行仕様ではない。画像保全の指示は引き続き有効。
- サイトごとに独立した似た色を追加せず、共通青・事業色・文字用の濃色・淡い背景色を名前付きトークンで管理する。

## グラデーションの形と強さ

全サイトで左上を起点に右下へ円状に広がる。色順が逆でも、円の中心を右下に移動して形を反転しない。公式は青から黒系へ、事業サイトは各テーマ色から共通青へつなぐ。

ユーザーの最終判断は「ロゴの円に影のようにサブカラーがかかり球のように見え、サブカラーも色として認識できる範囲」。面積の何割を青で固定するかではなく、混色の強さと滑らかさで調整する。大きな単色領域の直後だけ急変させない。小さな色斑を多数重ねない。

### ロゴ中央の球

見本の `--sphere-paint` を基準とする。主な色面は `ellipse 90% 90% at 28% 22%`、柔らかな光は `ellipse 45% 35% at 30% 22%`。光は白の約33%から透明へ落とし、右下へ補助色が回り込む。

公式・Systems・Schoolsは、主色0%/28%、主色78%と補助色22%の混色を52%、主色42%と補助色58%の混色を75%、補助色を100%へ置く。ここでいう百分率はCSSの色停止点・混色係数であり、円の面積比率ではない。

Designsは黄0%、橙28%、ピンク48%、紫66%、青100%。光の形・方向は他と共通。中央円以外のロゴ外形、余白、比率、文字の形を勝手に変えない。SVGではCSSと同じ見え方を意図して停止点・焦点・重ね方を実装し、最小表示サイズでも色と輪郭を確認する。

### 外周の立体感と背景別のロゴ

同日の最新修正では、金属的な反射筋・白い光沢・矢印の折り目を避け、マットで穏やかな厚みへ調整した。リングは幅広い曲面の陰影、矢印は面全体の滑らかな濃淡とし、小サイズで主張せず拡大時に厚みが分かる範囲を保つ。平面の単色へ戻さず、停止点の多い明暗反復も再採用しない。

承認済み外周SVGのリングはuserSpace上の中心`187.5/187.5`、焦点`171/160`、半径`190`、停止点`0/58/100%`。黒系は`#182039 / #303950 / #11182f`、薄色は`#e5ebf4 / #f2f6fb / #dbe4ef`、濃背景用は`#e3ebf4 / #f0f5fa / #d5e0ed`。明るい山を広く内側へ寄せ、輪郭上に狭い光沢筋を作らない。

矢印は面全体に沿うlinearの`0/55/100%`。黒系は`#2a334b / #1c253e / #101831`、薄色は`#f2f6fb / #e8eef6 / #dce5f0`、濃背景用は`#f0f5fa / #e6edf6 / #d5e0ed`。中央の承認球と既存の形状・背景別選択は維持する。狭い反射筋を持つ以前の比較画像は履歴として扱い、公開比較ページの主表示とPNGはこの最新仕様へ揃える。

同日の追加指示により、中央の球だけでなく外周のマークにも控えめな立体陰影を付ける。中央と同じ左上からの光を基準に、外周の曲面にも滑らかな明暗を作る。元のpath・clip座標・形状・比率・余白を保ち、fillとgradientで質感を揃える。中央円のみの色変更に限定していた旧実装記録より、この追加指示を優先する。

- 明るい背景では、既存の黒系と薄色の組み合わせを保ち、両方に柔らかい陰影を付ける。
- 濃い背景では外周全体を薄色へ切り替え、白から淡い灰青の明暗で全体の形を認識できるようにする。中央の球は各テーマ色のまま維持する。
- 全体を白くするフィルターや、白い四角の下地を置くだけで済ませない。薄色の外周と色付きの球を両立する。
- 文書内のロゴは実際に載せる背景に応じて明背景用・濃背景用を選ぶ。OSがダークモードであることだけを理由に、白いヘッダー上のロゴまで薄色へ変えない。faviconのブラウザ外観への対応と、文書内画像の背景への対応を分ける。
- OGなどの濃い背景も同じ規則に従う。16/32/64pxと拡大表示を明暗の両背景で比較し、外周が消えず、中央の色と左上からの光が一致することを確認する。

### 色帯・枠線・操作部品

見本の `--paint` を基準とする。左上側の柔らかな同系色の重なりと、`ellipse 110% 160% at -10% 0%` の主グラデーションを使う。球の光沢をすべての本文背景へ敷き詰めない。

公式は青が主役のまま黒を滑らかに混ぜる。事業サイトではテーマ色を主役にしながら、右下の青を独立した色として認識できる強さで残す。細い枠線や小さい丸への適用では、大きい見本だけで判断せず実サイズを確認する。

## 文字と適用範囲

承認後の同日追補：「テーマカラーは適度に使わないと逆に見ずらい」というユーザー指示を優先する。全サイトの一貫性は、全要素の着色を意味しない。承認見本はロゴ・配色・混色方法の基準として保持するが、見本内の見出し着色を全ページへ一律に展開しない。

- ヘッダー等の `Acecore` は共通青。`Systems` は紫、`Schools` は緑、`Designs` は読みやすい多色。スラッシュ等の区切りは中立色。
- テーマカラーはロゴ中央、favicon、ヘッダー・フッターのロゴと事業名、短いラベル、主要CTAの縁と文字、ナビゲーションの選択状態、要所の罫線へ絞って使う。検索・AIも同じ使い分けに揃える。
- 通常のh1/h2/h3（大きいHero見出しを含む）、本文、料金数値は原則として中立色 `#20252B`。色ではなく字級・太さ・余白で情報の階層を作る。事業名としての見出しは識別色を使える。
- 背景は白を主体にし、淡い色面は必要なまとまりに限定する。すべてのセクションを色付きにせず、通常の表・カード枠・区切りは中立色を維持する。多色や球状の表現を全見出し・全本文・全カードへ反復しない。
- 公式サイト内の事業案内は、Systems紫・Schools緑・Designs多色に揃える。Designsを単色紫に戻さない。
- 長文・補足文は読みやすい中立色を維持できる。成功・警告・エラーの意味色、写真・実作品・記事図の内容上の色を無理にテーマ色へ塗り替えない。
- 背景に応じて文字用濃色や読み面を使い、淡い主色に白文字をそのまま重ねない。多色文字は最も薄い部分も確認する。ロゴは上記の背景別の外周を使い、一括白化フィルターで中央の色を消さない。

## 保全・確認・今後の変更

既存内容・価格・条件・記事・翻訳・CMS・フォーム・検索・AI・多言語経路を保持する。元画像とHattを含む素材は維持し、画像の差し替えは個別の指示を待つ。今回の配色確定は、素材差し替えや承認見本の仮コピー採用を意味しない。

変更時は全ページ家族と共有UIを棚卸しし、旧テーマのハードコード・重複override・未反映のロゴを確認する。デスクトップ・モバイル、メニューや検索の開状態、フォーカス・ホバー、長い翻訳、白/濃色背景、小さいfaviconを確認する。色だけで状態を伝えない。

各repoのbuild、変更ファイルのformat、diff check、必要な既存検証を実施する。実装・ローカル検証・CI・Preview・マージ・本番は別の状態として記録し、承認済み見本があることだけで本番反映済みとは扱わない。

対象リポジトリは `acecore-systems/acecore-net`、`acecore-systems/acecore-systems`、`acecore-systems/acecore-schools`、`acecore-systems/acecore-designs`。各repoのAGENTS・設計ガイドから本書を参照し、後続作業の開始時にも読み込めるようにする。
