# 企業サイト全体の案内と画像の使い方

確認日: 2026年10月23日

## 対象と判断方法

対象はAcecore公式サイト全体。ホーム・事業・会社概要だけでなく、ニュース一覧と記事、タグ・著者・アーカイブ、問い合わせ、検索、チャット、AceStudio、法務ページ、404、多言語、共通のヘッダー・フッターを含む。各ページを変えること自体を目的にせず、読者の目的を満たすまでの経路を確認する。

1. 読者がその場所で知りたいこと・選びたいことを特定する。
2. 既存の本文・図・カード・ナビが同じ役割を果たしていないか確認する。
3. 参考サイトでは、その要素が前後の説明や移動先とどうつながるかを見る。
4. Acecoreの事実・規模・提供内容に合わせ、維持・統合・削除・変更を決める。
5. デスクトップとモバイルでページ全体と次の移動先まで確認する。

同じ行き先のリンクがあるだけでは重複とは判定しない。冒頭の案内、長い本文を読んだ後の相談、フッターからの再移動は役割が異なる。一方、隣接する図とカードで同じ分類・説明・行き先を繰り返し、新しい判断材料が増えない場合は統合する。

## ページ・共通UIの役割

| 対象                     | 読者の目的                                       | 確認点                                                                                 |
| ------------------------ | ------------------------------------------------ | -------------------------------------------------------------------------------------- |
| ホーム                   | 会社を知り、事業・会社情報・相談・最新情報へ進む | ヒーローと直後の案内に同じ選択肢を重ねない。                                           |
| 事業紹介                 | 提供内容と詳細確認先を選ぶ                       | 部門・個別サービス・料金の役割を分け、同じ部門を何度も説明しない。                     |
| 会社概要                 | 法人情報・責任者・考え方を確認する               | 法人情報の途中に理念イメージを挟まない。標語・理念・目指す姿を見分けられるようにする。 |
| ニュース一覧・記事       | 情報を探し、読み、関連情報へ進む                 | 画像・日付・題名を統一。記事末の関連記事・タグ・戻る導線を区別する。                   |
| タグ・著者・アーカイブ   | 特定の切り口で記事を絞り込む                     | 現在の絞り込みと全体へ戻る方法、空表示、記事群の反復を確認する。                       |
| 問い合わせ               | 窓口を選び、必要事項を伝える                     | 専門サイト案内とフォームの役割、説明と入力欄の対応、未入力・エラー状態を確認する。     |
| 検索・チャット           | 情報を探す／相談内容を整理する                   | 機能の違い、閉じる・戻る・結果への移動を確認する。                                     |
| AceStudio                | 準備状況と問い合わせ先を確認する                 | 実績や受付内容を推測で補わない。                                                       |
| 法務・404                | 条件を読む／見つからないページから回復する       | 法務本文を装飾で薄めない。404から有効な行き先へ進める。                                |
| ヘッダー・フッター・言語 | 現在地を把握し、どこからでも移動する             | モバイルメニュー、キーボード、言語変更先、重なり、横はみ出しを確認する。               |

## 画像・図の採否基準

画像ごとに、説明対象、本文との対応、実写記録かイメージか、代替テキスト、切り取り、モバイル表示を確認する。

- 企業イメージは理念の雰囲気を補う用途。社員・顧客・実施済みイベントの証拠と誤認させない。
- サービス画像は提供内容や成果物を具体的に伝えられる場合に使う。装飾画像で説明を置き換えない。
- 図は関係・手順・比較を把握しやすくする場合に限る。既存カードの名称を図形にしただけなら統合・削除する。
- 近い場面の写真は、異なる情報を与えるか確認する。キャプションの言い換えだけでは追加理由にならない。
- 他社の文章・画像・商標・事例をAcecoreのものとして転用しない。参考にするのは情報の順序と視覚表現の役割。
- 生成や差し替えは、既存の適切な素材では説明できないときに行う。枚数を改善の指標にしない。

## 検証と公開の境界

日本語source、8言語の翻訳、CMSの項目をそろえる。build、content、corporate、SEO、対象ファイルのPrettier、差分検証を基本とし、変更した共有機能の既存テストを実行する。

ブラウザでは見た目だけでなく、会社理解、サービス選択、ニュース閲覧、相談、検索、言語変更、404からの復帰を確認する。route・画面幅・操作・結果・未確認範囲を作業記録に残す。問い合わせ送信や本番チャットの応答は、静的Previewの確認と区別する。

前回の3ページ・3言語・2画面幅の18画面確認だけでは、今回の全体改修の受け入れ条件を満たさない。全体監査と修正後の検証結果を別途記録する。

この作業はDraft PRとPreviewまで。merge・本番公開は別の判断とし、CI成功を本番反映と呼ばない。調査タブと確認サーバーは作業後に閉じ、未完了PRのブランチは引き継ぎ用に残す。
