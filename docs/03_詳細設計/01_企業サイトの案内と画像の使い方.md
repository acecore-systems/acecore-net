# 企業サイトの案内と画像の使い方

確認日: 2026年10月23日

## 参考にした公式サイト

| 参照先                                                                  | 実画面で確認した使い方                                                      | Acecoreへの反映                                                                                          |
| ----------------------------------------------------------------------- | --------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| [サイボウズ・企業理念](https://cybozu.co.jp/company/philosophy/)        | 標語、説明、下位見出しを分け、会社内の案内から目的の内容へ進める。          | 会社概要に法人情報・役員・企業理念・目指す姿へのページ内案内を置く。                                     |
| [Goodpatch・サービス](https://goodpatch.com/ja/service)                 | 短い価値説明の後に、UX Designと支援領域の全体関係図を示し、各詳細につなぐ。 | 事業ページ冒頭に共通理念と並列3部門の関係図を置き、各部門の本文へつなぐ。                                |
| [サイバーエージェント・サービス](https://www.cyberagent.co.jp/service/) | 事業領域、短い分類、矢印を大きなクリック領域で示す。                        | 事業の部門・主要サービス・料金の確認先を分け、カード内のリンク文言と外部サイトアイコンで行き先を伝える。 |

会社の規模や事業構成は異なるため、見た目や文章、素材を転用しない。既存の青色、罫線、角丸、カードを使い、情報の分け方と図の役割を取り入れる。

## ページの役割と案内

- ホームは「事業紹介」「会社概要」「お問い合わせ」の入口と企業ニュースを掲載する。ヒーロー内にも事業紹介・会社概要へのリンクを置く。
- 事業ページは事業部門、主要サービス、料金の目安を分ける。料金と対応内容の詳細は各専門サイトで確認する。
- 会社概要は法人情報、役員、企業理念・目指す姿を掲載する。理念本文は最新の正式文書と一致しているため原文を保ち、見つけやすさを改善する。

## 図と写真の役割

| 場所               | 内容と役割                                                                     | 表現上の条件                                                                                                                        |
| ------------------ | ------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------- |
| ホームのヒーロー   | 協働を想起させる既存の2枚スライドで、理念の要約を補う。                        | 画像から実在社員や実績を推測させる説明を加えない。                                                                                  |
| 事業のヒーロー     | Acecoreの共通理念とSystems・Schools・Designsの並列関係を示す独自のHTML/CSS図。 | 工程や序列と混同するStep・循環矢印を使わない。部門名を選ぶと本文へ移動する。Aceserver・Store・AceStudioは主要サービス欄で案内する。 |
| 会社概要のヒーロー | 既存のチームイメージで会社紹介への入口を作る。                                 | 写真の切り取り位置を維持し、人物紹介とは分ける。                                                                                    |
| 会社概要の理念直後 | PCを囲む協働の場面と、学習を隣で支える場面を2つのfigureで示す。                | 法人情報と役員の間から移し、異なる意味のキャプションを付ける。イメージであると明示する。                                            |

事業構成図はテキストとリンクで構成し、装飾の線とアイコンに説明を依存しない。モバイルでは3部門を縦に並べ、共通の枝から分かれる表現を保つ。会社概要では同じ関係図を繰り返さず、写真が理念の具体的な場面を補うようにする。

日本語source、8言語の翻訳、CMSの項目をそろえる。画像や図の変更時は、本文との対応、代替テキスト、リンク先、モバイルの折り返しを確認する。

## 検証と引き継ぎ

ローカルの生成出力を対象に、build、content、corporate、SEO、対象ファイルのPrettier、差分検証を行う。ブラウザ確認はトップ→事業紹介→料金の目安、事業構成図→部門、会社概要→企業理念・目指す姿を対象とする。

2026年10月23日の確認では、build、content、corporate、SEOが成功した。IABはこの実装作業側で `Browser is not available: iab` となったため、Playwright管理Chromiumの専用一時プロファイルを使用した。日本語・英語・ドイツ語のホーム・事業・会社概要を1440×1000と390×844の計18画面で確認し、ページ内移動とヒーローのリンク、横はみ出しなし、ブラウザの警告・実行時エラーなしを確認した。9言語全体の項目、CMS、本文、リンクとアンカーの整合性はcorporate検証で確認した。

この作業の対象はDraft PRまでとし、mergeと本番公開は別の判断とする。CI・Cloudflare Pages Previewの結果はPRで確認する。完了した調査タブとローカルの確認サーバーは閉じ、PRの作業ブランチを引き継ぎ用に残す。
